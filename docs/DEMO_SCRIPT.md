# Judge Demo Script

Target length: 2 to 3 minutes.

## Opening, 15 seconds

"Merchant Revenue Autopilot is an AI growth agent for Razorpay merchants, but the model is deliberately not trusted with authority. AI can propose an experiment. Deterministic policy authorizes it. The execution layer acts. Fixed-horizon statistics decides whether the treatment should be kept, rolled back, or marked inconclusive."

Open the live Overview page:

https://merchant-revenue-autopilot-psi.vercel.app/overview

## Step 1: show the merchant problem, 25 seconds

Point to:

- baseline conversion
- captured GMV
- weakest segment
- payment-method performance
- completed Autopilot state

Say:

"The system starts from payment data, not a chat prompt. Metrics and opportunity detection are deterministic. The detector compares a segment with the rest of the merchant cohort and creates evidence the model can reference."

The hosted dashboard contains experiment traffic from preserved demo cycles, so its total attempt count is higher than the canonical 6,112-attempt baseline. Do not present the current dashboard total as the frozen baseline size.

## Step 2: open the latest completed cycle, 45 seconds

Open **Autopilot**, then select the row marked **Latest cycle** for opportunity `a1761032`.

Point to **Observed Evidence** first.

Say:

"This section is observed evidence. The model cannot invent evidence keys because every reference in its response is validated against this catalog. In this run the android_budget segment was converting at about 47.5% versus 58.6% for the comparison cohort."

Move to the visible **AI ANALYSIS · GENERATED BY LLM** trust divider.

Say:

"Only below this boundary does the LLM participate. In this verified run it proposed enabling partial payment with a 25% minimum first payment because insufficient-funds failures were prominent. That is a hypothesis, not an authorized action."

## Step 3: show deterministic control, 35 seconds

Point to **Experiment Plan** and **Policy Authorization**.

Say:

"The planner turns the hypothesis into a canonical test. This plan uses 10% treatment exposure, 200 minimum samples per variant, a 72-hour maximum duration, a fixed primary metric, and explicit guardrails. Then merchant policy authorizes or rejects the complete experiment. There is no override button and no silent parameter clamping."

If asked about an unsafe proposal, explain that policy returns explicit violation codes and stops the cycle.

## Step 4: disclose hosted execution honestly, 20 seconds

Point to **Simulated Payment Resource**.

Say:

"The repository contains a real Razorpay Test Mode client and executor. The public hosted demo uses an explicit simulated execution adapter because this account could not obtain Test Mode API credentials without merchant onboarding and KYC. The product labels this clearly, uses a demo-prefixed resource ID, and states that no Razorpay API request was made."

The currently verified demo resource is `demo_plink_8b6f752dd2126b8a`.

Do not claim the `demo_...` resource exists in the Razorpay dashboard.

## Step 5: show the statistical decision, 30 seconds

Point to the final **Statistical Result**.

Say:

"The experiment does not stop on an interim trend. It waits for the fixed sample horizon. This completed run measured 46.9% control conversion and 46.0% treatment conversion. The absolute lift was only minus 0.9 percentage points, p was 0.8071, and the confidence interval crossed zero. So the deterministic decision was INCONCLUSIVE. The LLM does not participate in this decision."

This is a useful demo result because the system does not force a positive or negative conclusion when the evidence is weak.

## Step 6: show repeatability and audit integrity, 25 seconds

Return to **Autopilot** briefly and point out that both completed cycles are still present: the latest cycle and the earlier 28 Aug cycle.

Then open **Audit Log**.

Say:

"A new optimization run does not wipe the old result. Both cycles remain in the same merchant history. Every lifecycle transition is hash-chained: opportunity, AI diagnosis, plan, policy, execution, runtime, and statistics. The dashboard verifies the chain."

Do not click **Start New Optimization Cycle** during the normal judged demo. The current terminal state is intentionally stable. If a judge asks whether repeat execution works, explain that production verification already exercised rollover and proved that rollover is rejected while a cycle is active or deployed.

## Step 7: finish with benchmark evidence, 25 seconds

Open `docs/evaluation/summary.md` in GitHub.

Say:

"The live cycle is one run, so I also built a frozen paired benchmark. Across five seeds, five merchant segments, and 5,000 contexts per segment, Autopilot averaged 59.39% conversion versus 58.18% with no optimization, a plus 1.22 percentage-point mean delta. The rule baseline was minus 0.52 points overall. These are synthetic deterministic results, not production revenue claims."

Close with:

"The contribution is not another AI recommendation dashboard. It is the control architecture around an AI revenue agent: evidence grounding, deterministic authorization, duplicate-safe execution, statistical decision-making, and tamper-evident audit."

## If the live backend is waking from Render free-tier sleep

Do not repeatedly click lifecycle actions. Refresh the Overview page once and wait for the backend to respond. Read-only pages are safe to retry. Mutation buttons should be clicked once per intended transition.

## Verified production fallback

If a live mutation is not appropriate during judging, use the preserved latest cycle rather than starting another run. The release verification already exercised the hosted flow end to end:

`HYPOTHESIS_PROPOSED -> EXPERIMENT_PLANNED -> POLICY_APPROVED -> RESOURCE_DEPLOYED -> EXPERIMENT_BATCH_RUN x4 -> EXPERIMENT_EVALUATED`

It also verified `409 INVALID_TRANSITION` rollover protection before continuation and again after deployment, preserved the earlier cycle, ended `INCONCLUSIVE`, and kept the audit chain valid.

## Things not to claim

- Do not call hosted `demo_...` resources real Razorpay resources.
- Do not call synthetic benchmark GMV production revenue.
- Do not say the LLM decides experiment success.
- Do not say the audit chain is a blockchain.
- Do not imply the benchmark uses live OpenRouter responses. Its diagnosis adapter is deterministic for reproducibility.
- Do not describe the 10,163-attempt hosted dashboard total as the canonical baseline; experiment traffic is appended across preserved cycles.
